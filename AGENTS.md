# Architecture rules

- Keep technology classification in the shared primary-IPC classifier and version the statistics cache whenever mappings change; this keeps frontend labels and server counts consistent without serving obsolete merged categories.

- Normalize commercialization prose through the shared summary presentation helper before parsing web or print output, so cached and newly generated summaries follow the same formatting rules.- Domestic market figures registered in the KOSIS series list (summarize-patent/kosis.ts) take their base value and CAGR from official statistics (refreshed every 30 days) and override AI-written numbers, so the same market always shows the same official figures.
- Market figures are pinned per market in market_reference (domestic KRW and global USD alike); stored values are injected into the summary prompt and re-applied after generation, so the AI reuses existing markets instead of inventing new numbers.

## Architecture decisions
- Accumulate only server-cache-verified, applicant-scoped original source excerpts through the shared analysis-case policy; never recycle AI claims, scores or market figures as truth, and audit policy/source/reference IDs without invalidating existing scores.
- TRL presentation uses the shared reference levels and legacy-default resolver across admin, summaries and PPT; terminology updates must not change inferred scores or overwrite custom labels.
- Define summary section content budgets in the server-side sectionBalance helper and version the prompt on policy changes; preserve full prose rather than truncating web or print output.
- Keep homepage search presentation in HomeSearchHero and shared semantic CSS tokens so one layout stays consistent across screen sizes without changing search behavior.
- Technology tile tone classes (`technology-tile-<tone>`) are safelisted in tailwind.config.ts because they are composed dynamically (`technology-tile-${tone}`) and would otherwise be tree-shaken from the CSS output. Never remove the safelist.
- The company-profile patent finder (find-my-patents) retrieves candidates only through search-patents and keeps scope/ranking rules in its finderPolicy module; AI rankings may only reference retrieved, applicant-scoped candidates so no patent is ever invented.
- The Insights filing-trend report is aggregated server-side (filing-trends) from complete applicant-scoped KIPRIS pages, compares only fully disclosed years (18-month publication lag) and keeps AI summary sentences only when every number matches the computed statistics.
- The home 특허 인사이트 section renders the filing-trend summary and a compact field ranking from the single useFilingTrends snapshot (same as the Insights page), so home and Insights never show conflicting numbers; ranking rows keep their field-search navigation.
- Secret-scan exceptions live in .gitleaks.toml as narrow line patterns for verified public values only (publishable client settings, cache key names) on top of default rules, so real credentials are still reported; keep bun.lock and package-lock.json resolved to the same patched versions so external dependency scanners match. Regenerate package-lock.json with npm 11 (npm 10 crashes on this tree).
- Delete server functions and UI modules once no screen calls them (verify by searching src), so unused public endpoints never stay deployed.
- Toolchain is Vite 6, Vitest 4 and React Router 7 (imported via react-router-dom) to stay clear of known advisories; keep tsconfig lib at ES2020-safe APIs since Vitest no longer pulls in newer lib types.
- Sentence-style (natural-language) searches filter and rank results by title coverage of AI-extracted concept groups (each core term with its own synonyms) in search-patents/nlRelevance.ts; abstract hits, conversational words and generic terms never qualify a result, so weakly related patents are dropped rather than shown.
- The home 물어보기 assistant (patent-chat) answers only from data it retrieves per question — search-patents results filtered to the 6 institutes, the filing-trends snapshot, stored patent_score_cache scores and the fixed transfer guide — with routing/card rules in chatPolicy.ts; patent cards come from that server data (never from model text), so no patent, score or statistic is ever invented. Chat UI uses AI Elements under src/components/ai-elements and is lazy-loaded so the home bundle stays light.
