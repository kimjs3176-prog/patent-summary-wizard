# Architecture rules

- Keep technology classification in the shared primary-IPC classifier and version the statistics cache whenever mappings change; this keeps frontend labels and server counts consistent without serving obsolete merged categories.

- Normalize commercialization prose through the shared summary presentation helper before parsing web or print output, so cached and newly generated summaries follow the same formatting rules.- Domestic market figures registered in the KOSIS series list (summarize-patent/kosis.ts) take their base value and CAGR from official statistics (refreshed every 30 days) and override AI-written numbers, so the same market always shows the same official figures.
- Market figures are pinned per market in market_reference (domestic KRW and global USD alike) with a trust status: official (KOSIS) and approved (admin-reviewed with a source) values are injected into the summary prompt as standards with their citation; new AI-written figures are stored only as ai_pending (no source, CAGR 0–30%), listed to the model as unverified estimates, and every sentence they back is labelled "(AI 추정치)" instead of an institution citation. All statuses are re-applied after generation as one set per market (base, CAGR, projections) so the same market keeps the same numbers; admins review ai_pending values in 요약서 → 시장 표준값 검토.

## Architecture decisions
- Accumulate only server-cache-verified, applicant-scoped original source excerpts through the shared analysis-case policy; never recycle AI claims, scores or market figures as truth, and audit policy/source/reference IDs without invalidating existing scores.
- TRL presentation uses the shared reference levels and legacy-default resolver across admin, summaries and PPT; terminology updates must not change inferred scores or overwrite custom labels.
- Define summary section content budgets in the server-side sectionBalance helper and version the prompt on policy changes; preserve full prose rather than truncating web or print output.
- Keep homepage search presentation in HomeSearchHero and shared semantic CSS tokens so one layout stays consistent across screen sizes without changing search behavior.
- Technology tile tone classes (`technology-tile-<tone>`) are safelisted in tailwind.config.ts because they are composed dynamically (`technology-tile-${tone}`) and would otherwise be tree-shaken from the CSS output. Never remove the safelist.
- The company-profile patent finder (find-my-patents) retrieves candidates only through search-patents and keeps scope/ranking rules in its finderPolicy module; AI rankings may only reference retrieved, applicant-scoped candidates so no patent is ever invented.
- The Insights filing-trend report is aggregated server-side (filing-trends) from complete applicant-scoped KIPRIS pages, compares only fully disclosed years (18-month publication lag) and keeps AI summary sentences only when every number matches the computed statistics.
- The home 특허 인사이트 section renders the filing-trend summary and a compact field ranking from the single useFilingTrends snapshot (same as the Insights page), so home and Insights never show conflicting numbers; ranking rows keep their field-search navigation.
- Secret-scan exceptions live in .gitleaks.toml as narrow line patterns for verified public values only (publishable client settings, cache key names) on top of default rules, so real credentials are still reported; keep bun.lock and package-lock.json resolved to the same patched versions so external dependency scanners match. Regenerate package-lock.json with npm 11 (npm 10 crashes on this tree).
- Delete server functions and UI modules once no screen calls them (verify by searching src), so unused public endpoints never stay deployed.
- Toolchain is Vite 6, Vitest 4 and React Router 7 (imported via react-router-dom) to stay clear of known advisories; keep tsconfig lib at ES2020-safe APIs since Vitest no longer pulls in newer lib types.
- Sentence-style (natural-language) searches filter and rank results by title coverage of AI-extracted concept groups (each core term with its own synonyms) in search-patents/nlRelevance.ts; abstract hits, conversational words and generic terms never qualify a result, so weakly related patents are dropped rather than shown.
- The home 물어보기 assistant (patent-chat) answers only from data it retrieves per question — search-patents results filtered to the 6 institutes, the filing-trends snapshot, stored TRL values (commercialization scores are left to the patent summary) and the fixed transfer guide — with routing/card rules in chatPolicy.ts; patent cards come from that server data (never from model text), so no patent, score or statistic is ever invented. Chat UI uses AI Elements under src/components/ai-elements and is lazy-loaded so the home bundle stays light.
- First paint is owned by a static #boot-splash in index.html that SplashScreen takes over (same background) and removes; html[data-splash] pauses page entrance animations until the splash fades, and site settings render from a browser snapshot while refreshing, so the first load never flashes white, replays or jumps.
- Home loads result-only screens (summary, quick nav, satisfaction) lazily and the one-time service-worker reset reloads only clients that actually had leftovers, so first visits stay light and uninterrupted.
- The home and search-results search boxes classify each entry in src/lib/queryIntent.ts (number/batch → summary, 1–2 words → broad keyword search, described needs → strict sentence search, questions → patent-chat opened in place) and the home and results-page boxes share SmartSearchBox; its keyword/sentence split mirrors isNaturalLanguageQuery in search-patents, so change both together.
- 출원지원 (filing) is an optional embed of the separate 에이프 app (src/lib/filing.ts, src/pages/Filing.tsx): the /filing page frames the bundled copy at `/filing-app/` by default (public/filing-app/index.html, a filing-only build of 에이프 with the landing/3D island/AIS/global views stripped; `filing_url` may point at an external https host instead) with `?embed=ais&skin=ais&accent=…#step` (hides its header, rail, page bar and footer and applies this site's palette/font); its `/api/*` calls go to the `filing-api` edge function named by the page's `<meta name="filing-api">`, whose `lib/` started as a copy of 에이프 `server/*.js` (process.env shim in lib/env.ts). Both copies are now owned by this repo: there is no sync from kimjs3176-prog/koat-axlab any more, so make every 출원도우미 change directly in public/filing-app/index.html and supabase/functions/filing-api/lib/ here and never in koat-axlab. The page draws the step tabs, sub-page chips, prev/next, D-day, help and settings in this site's design from the `agri-ip:state` message 에이프 sends on every render; the two apps talk only by postMessage checked against the configured origin (state/ais from 에이프; go/move/open/cite into 에이프), and parseFilingMessage bounds every field before use. The feature_filing site setting (default on) gates the home 출원도우미 link (beside the 통합검색/나만의 특허찾기 tabs in HomeSearchHero), the summary ActionBar button and the search-results button together, and filing_url accepts https only; 에이프 keeps its own state in the browser, so nothing is stored on this side.
- Layout stability and accessibility are measured with Lighthouse on mobile and desktop (target CLS < 0.1, accessibility ≥ 95). Keep them: content that arrives later reserves its space (PageLayout renders at once with default or last-seen settings and its content area is min-h-screen so the footer never jumps; the summary shows a placeholder until the patent record arrives; its side columns keep their width; the ActionBar renders from the start with print/regenerate disabled while streaming; the analysis progress card floats at the bottom), web fonts load without blocking the first paint, text uses full-strength muted colours (no /40–/60 opacity on readable text, summary meta grey #6B7684), icon-only controls carry aria-label, and a link styled as a button is `<Button asChild><Link/></Button>` (never a button inside a link). <link rel="canonical"> follows the route (src/lib/canonical.ts).
- The service collects no personal information: no forms that take names, contacts or free-form identity data, and no server-side records about visitors beyond aggregate counts. The summary's 기술이전 신청 button links out to NATI; nothing on this side collects or stores inquiry data.

## Lovable ↔ Claude co-editing
- The site is built and hosted on Lovable (Lovable Cloud backend); this GitHub repo is the shared source both sides edit. Lovable commits straight to main; Claude works on its own branch started from the latest origin/main, opens a PR, and merges only when the owner asks. Before starting any change, fetch main so Lovable's latest edits are the base, and keep each PR small so Lovable edits rarely collide.
- Do not hand-edit what Lovable generates or owns: src/integrations/supabase/types.ts and client.ts, the committed .env, and .lovable/. Schema changes go in a new supabase/migrations file (never edit an applied one).
- Lovable Cloud does not deploy Edge Functions or run migrations that arrive through GitHub; only Publish updates the screen. So a change is live only after (1) Publish for anything under src/ or public/, and (2) a deploy request in the Lovable chat for changed functions and new migrations. `node scripts/lovable-deploy-list.mjs <base> [head]` lists exactly which (a function counts as changed when its own files or any _shared module it imports, directly or indirectly, changed) and prints the sentence to paste into Lovable; CI writes the same list to every run summary (job "Lovable 배포 목록"). Every PR body states it, or says Publish alone is enough.
- Prefer changes that need no function deploy when the choice is free: screen copy, layout and the bundled 출원도우미 page (public/filing-app) ship with Publish alone, and site settings already stored in the database (admin page) change without any deploy.
