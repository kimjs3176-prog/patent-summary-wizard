# Frontend rules

- Normalize commercialization prose through the shared summary presentation helper before parsing web or print output, so cached and new summaries format the same way.
- The summary reads as a report (핵심 요약·목차 → sections with a lead sentence; market table and 공식 통계/AI 추정 badges) built by lib/summaryReport.ts from the server-labelled text; it only reads figures and citations, never changes them. Keep it short on screen: each prose section shows its lead and first paragraph and folds the rest behind '더 보기' (print and PDF always show everything via @media print, body.ais-printing and .ais-pdf-capture); AI 종합 의견 appears as its own section only when it is longer than the two sentences already in 한 줄 결론; the model's **bold** phrases render with a marker highlight. 관련 키워드 come from the patent title first (lib/patentKeywords.ts: 원료·용도·방식, then 형태·산업 from the rule dictionary), never generic category labels alone.
- TRL presentation uses the shared reference levels and legacy-default resolver across admin and summaries; terminology updates must not change inferred scores or overwrite custom labels.
- Keep homepage search presentation in HomeSearchHero and shared semantic CSS tokens. The home and results-page boxes share SmartSearchBox and classify entries in lib/queryIntent.ts (number/batch → summary, 1–2 words → broad search, described needs → strict sentence search, questions → patent-chat in place); its split mirrors isNaturalLanguageQuery in search-patents.
- `technology-tile-<tone>` classes are composed dynamically and safelisted in tailwind.config.ts; never remove the safelist.
- Home 특허 인사이트 and the Insights page both render from the single useFilingTrends snapshot so numbers never conflict; ranking rows keep field-search navigation.
- Chat UI uses AI Elements (components/ai-elements) and is lazy-loaded; home also lazy-loads result-only screens, and the one-time service-worker reset reloads only clients with leftovers.
- First paint is a static #boot-splash in index.html that SplashScreen takes over and removes; html[data-splash] pauses entrance animations until it fades, and site settings render from a browser snapshot while refreshing.
- Owner's UI style (summary and 출원지원): no duplicated elements or information across a screen and its surrounding chrome, no text-list explanations (use short labels, numbered step strips, badges), no left colour-stripe accents and no full-width stretched bar graphs (use counts, short fixed bars or small rings); each 출원지원 page has one title row with a step strip and one next action, and its AI never starts on page entry or input change — only from a start card or button the user presses (next is locked while it runs). Choices in 출원지원 use the shared seg() tiles (every option visible with a one-line plain meaning, ✓ on the picked one, a 추천 or 감면 badge where it helps, 예 before 아니요); keep native dropdowns only for long lists such as 지역 or 특허분류.
- Lighthouse targets (mobile and desktop): CLS < 0.1, accessibility ≥ 95. Late content reserves its space (PageLayout shows an empty min-h-screen block until settings first load and keeps a min-h-screen content area; the summary keeps placeholders, fixed side columns and an always-rendered ActionBar); fonts never block first paint; readable text uses full-strength muted colours (summary meta grey #6B7684); icon-only controls carry aria-label; a link styled as a button is `<Button asChild><Link/></Button>`; canonical follows the route (lib/canonical.ts).
- 출원지원 embeds the bundled 에이프 copy (public/filing-app/index.html, owned here; `filing_url` may point at an external https host) in pages/Filing.tsx with `?embed=ais&skin=ais&accent=…#step`; its `/api/*` calls go to the function named by `<meta name="filing-api">`. The page draws step tabs, chips, prev/next, the 남은 일 list (a step shows ✓ only when its `todo` is empty), D-day and help from `agri-ip:state`; AI runs only through filing-api's Lovable gateway (no key-entry settings); the apps talk only by origin-checked postMessage bounded by parseFilingMessage. feature_filing (default on) gates every 출원도우미 entry point together (hero link, header menu and home card via visibleServices, summary ActionBar, search results).
