# 보안 점검 기록 (2026-11-06)

점검 범위: React 앱(`src/`), 출원도우미(`public/filing-app/`), Edge Functions(`supabase/functions/`), DB 마이그레이션(`supabase/migrations/`), CI·의존성.
기준: 운영 담당자가 준 보안 검토 목록(SQL 인젝션 ~ 공급망 공격, 요청 크기 제한, 프롬프트 인젝션 등) 중 이 서비스 구조에 해당하는 항목.
로그인·회원이 없는 공개 서비스이고 관리자는 비밀번호 하나로 서버 함수에서만 확인한다는 점을 전제로 판단했다.

## 고친 것 (이번 패치)

| 항목 | 문제 | 조치 |
|---|---|---|
| XSS | 출원도우미 작업 파일(.json)을 불러오면 비교 특허 번호·검색 결과·링크가 이스케이프 없이 화면에 들어가 스크립트가 실행될 수 있었음(같은 출처라 관리자 화면까지 영향) | 불러온 파일의 검색 결과는 받지 않고 다시 찾게 함. 비교 특허는 13자리 번호만, 사진 도면 id·PNG 형식 검사. 링크는 `https://` 만. 공백 맵 축 이름·특허 번호 이스케이프. 화면을 그린 뒤에만 저장(깨진 파일로 앱이 계속 막히지 않게) |
| 비밀 관리 | 국유특허·등록원부 함수가 키를 넣은 요청 주소의 네트워크 오류 문구를 그대로 응답·로그에 남김 | 응답은 정해진 문구, 로그는 오류 이름만. export-patents·filing-api·sync-r2-videos 도 같게 |
| 입력 검증·요청 크기 | 용어 풀이·비슷한 특허·규제 분석의 제목·분류가 길이 제한 없이 AI 프롬프트에 들어감 | 제목 300자, 초록 3000자, 분류 20개×40자 |
| 무차별 호출·비용 | 출원도우미 서버가 조작 가능한 `x-forwarded-for` 첫 값으로 사용자를 구분하고, 함수 인스턴스마다 따로 셈 | 공용 식별(`callerIdentity`)과 DB 기반 5분 제한을 함께 |
| 무차별 호출·비용 | 일괄조회의 발명자 포함 조회가 한 번에 최대 500건 상세 조회(KIPRIS 공용 한도 소진 가능) | 50건 넘게 발명자까지 받을 때 10분에 12번으로 따로 제한 |
| SSRF | 그림 대리(proxy-image)가 리다이렉트를 자동으로 따라가고 크기 제한·호출 제한이 없음, SVG·원본 캐시 지시를 그대로 전달 | 리다이렉트마다 허용 목록·사설 IP 재검사(최대 3번), 8MB 제한, SVG 거부, 캐시 지시 고정, `nosniff`, 호출 제한 |
| 서버 측 권한 | 영상 목록 동기화(sync-r2-videos)를 누구나 반복 실행 가능 | 시간당 6번 제한 |
| 행 수준 보안 | 인기 검색 집계 함수가 화면이 보낸 제목을 그대로 저장 → 홈 인기 검색 제목 바꿔치기·순위 부풀리기 | 서버가 받아 둔 원문 제목만 쓰고, 원문 없는 번호는 세지 않으며, 같은 번호는 30초에 한 번만 셈. 쌓인 제목도 원문 제목으로 바로잡음 |
| 행 수준 보안 | 숨긴 추천 특허·공지(담당자 연락처 포함)를 공개 키로 직접 읽을 수 있었음 | 공개 읽기를 `is_active` 인 행으로 제한 |
| 비밀 관리 | 설정 표의 비밀값 차단이 대소문자를 가림(운영 DB 확인 결과 비밀값 행은 없음) | 대소문자 무시로 차단, 비밀값 성격의 행이 생겨도 삭제 |
| CORS·메시지 | 출원도우미 임베드가 문서 referrer 의 출처를 그대로 믿어, 어떤 사이트든 넣어서 작성 중인 명칭 등을 받을 수 있었음 | 이 사이트·AIS·Lovable 미리보기 출처만 |
| 파일 업로드·최소 권한 | 관리자 화면이 공개 키로 `tech-videos` 버킷에 직접 올리고 지움 → 버킷에 익명 쓰기 정책이 있어야 동작하는 구조(누구나 올리고 지울 수 있음) | 관리자 함수가 비밀번호 확인 뒤 한 번 쓰는 서명 업로드 주소를 내주고(MP4·WebM·MOV, 500MB까지), 삭제도 함수가 함. 버킷 쓰기 정책은 이름과 상관없이 삭제 |
| 오픈 리다이렉트 | 관리자 로그인 뒤 `?next=//다른사이트` 로 바깥으로 보낼 수 있었음 | 사이트 안 주소만 |
| 프롬프트 인젝션 | AI 답의 그림 문법이 바깥 주소를 불러 대화 내용을 내보낼 수 있었음 | AI 답에서 그림은 그리지 않음 |
| 콘텐츠 보안 정책 | CSP 없음 | `object-src 'none'; base-uri 'self'; form-action 'self'` (meta). 스크립트 제한은 Lovable 미리보기·인라인 스크립트 때문에 보류 |
| 종속성 취약점 | 매일 점검이 개발 도구(eslint·drizzle-kit)의 '보통' 등급 때문에 늘 실패할 구조 | 운영 의존성은 '보통' 이상 실패, 개발 도구는 'high' 이상만 경고 |

## 확인했고 문제없는 것

- SQL 인젝션: 원시 SQL 없음. PostgREST `.or()` 입력은 정규식으로 거르거나 특수문자를 뺌. KIPRIS 파라미터는 `URLSearchParams`.
- CSRF: 쿠키·세션이 없고 관리자는 매 요청 본문의 비밀번호로 확인 → CSRF 경로 없음. CORS `*` 도 자격 증명 없이만.
- 대량 할당: 관리자 함수의 추천 특허·공지·설정 저장은 필드를 하나씩 골라 길이를 자름.
- 해싱·소금·타이밍 공격: 관리자 비밀번호는 PBKDF2-SHA256 120,000회 + 소금, 상수 시간 비교, 실패 15분 5회 제한. (OWASP 권장 60만 회보다 낮지만 매 관리자 요청마다 검증하는 구조라 함수 CPU 한도를 고려해 유지)
- 계정 열거·세션 고정·JWT·OAuth·MFA: 회원·세션이 없어 해당 없음. 관리자 MFA 는 계정 체계가 생길 때 검토.
- 비밀 스캐닝: CI·매일 점검에서 gitleaks. 커밋된 `.env` 에는 공개 anon 키만(역할 `anon` 확인).
- HSTS·nosniff·Referrer-Policy: 운영 사이트 응답에 있음.
- 개인정보: 수집하지 않음. 만족도 자유 의견은 관리자(서비스 롤)만 읽음.
